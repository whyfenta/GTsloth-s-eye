# 處方警示規則表（草稿）

> **狀態：藥師審核中。** 規則表由先前的開發 session 憑藥學知識起草，尚未逐條對照仿單。「依據」欄（仿單、指引、常見、常見仿單外）是起草者的判斷，不是查證過的結果。藥師已審過第一批（見下方「藥師審核」），還有 32 條未審。網站的處方警示預設關閉，藥師審完規則表才打開，開關見 README「處方警示」。

檔案：[`rx-rules/`](rx-rules/) 底下 6 個 CSV，UTF-8（含 BOM）。前 5 個（適應症、同處方、注意事項、科別、藥品分類）從規則草稿資料夾原樣複製；`settings.csv` 是這次新增的，把需要藥師決定的做法從程式移到表格。

用途：`npm run rx-assets` 逐列檢查後轉成 `public/assets/rx/rules.json`，由 `src/rx-check.ts` 判定。判定邏輯照規則草稿的 Python 原型 `check_rules.py`（不在 repo 裡），兩者對每個藥的判定以本機樣本比對一致，見下方「試跑與比對」。

## 判定方式

每個藥依序判定，前一層解釋得了就停：

1. **適應症**（`indications.csv`）：本次的某個診斷碼可以解釋這個藥。同一個藥對到多列時，依「依據」先試仿單、再指引、常見、常見仿單外，其他寫法最後；同一種依據照檔案順序。
2. **同處方**（`co-drugs.csv`）：同一張處方上的另一個藥可以解釋它，例如抗血小板藥解釋胃藥。同一個健保碼開兩次不算。網頁仍把這類藥列為灰色提示（藥師審核：因別的藥而開的藥也要提示，但不必到黃色）。
3. **科別常用**（`specialty.csv`）：QR 第 7 欄的就醫科別常開這類藥。`settings.csv` 可以停用這一層。
4. **低風險**（`drug-classes.csv` 類型「低風險」）：不提示。
5. 都解釋不了：高警訊藥（`drug-classes.csv` 類型「高警訊」）給黃色，其他給灰色。處方沒有診斷碼時一律灰色。

另外：

- **注意事項**（`cautions.csv`）：不論上面判定的結果，每個藥都另外比對。藥品以 ATC 或成分關鍵字對上後，看條件：診斷（本次有這些診斷碼）、年齡（年齡層至少幾歲或未滿幾歲）、性別（QR 第 5 欄身分證字號的第 2 碼，1 男、2 女）、同處方（同一張處方有這些 ATC 的藥，可限定那個藥的頻率）。一條可以有多種條件，全部成立才提示；有一種不成立就不提示；其餘成立、但有一種無法判斷時給灰色：年齡層跨過門檻時「無法判斷」，沒有生日或生日格式認不得時「無法讀取年齡」，第 2 碼不是 1 或 2（例如部分外籍人士的居留證）時「無法取得性別資料」。
- **較具體的注意事項取代較一般的**：同一個藥同時對到兩條注意事項，若兩條的 ATC 與成分關鍵字寫得一樣，而一條的條件包含另一條的全部條件還多幾項，只顯示條件多的那條。例如 C17 是 C09（65 歲以上用 BZD，灰色）再加上同處方有 α 阻斷劑或睡前降血壓藥，成立時只顯示黃色的 C17，這就是 C09「升一級」。
- **同成分重複**：同一張處方兩個以上不同健保碼含相同成分時提示，等級在 `settings.csv`。成分名去掉含量（MG、MCG、G、ML、IU、U、%）、括號與鹽類字尾（HCL、SODIUM 等）後比對，所以 INSULIN GLARGINE 和 INSULIN ASPART 仍是兩個成分。
- **沒有診斷碼的處方**：整張只給一則灰色提示，不對每個藥逐一提醒；注意事項照常比對。
- **不在健保用藥品項的代碼**（例如特材）：當成低風險，也不比對注意事項。
- 診斷碼比對前，QR 與規則兩邊都去掉小數點並轉成大寫。

## 寫法

- 一格有多個值時以半形空格分隔。
- **ATC**：寫前綴，例如 `C`（所有心血管藥）、`C10`、`C10AA`、`C10AA05`。
- **ICD-10-CM**：寫前綴，例如 `E11`、`N18.4`；或寫範圍，例如 `I10-I16`。範圍兩端的碼長要相同、前小後大，比對時取診斷碼的前幾碼（與範圍兩端同長）落在兩端之間，所以 `I20-I25` 包含 `I25.10`、不包含 `I26`。
- 等級只能是 `紅`、`黃`、`灰`。
- **注意事項的條件**：`條件類型` 寫 `診斷`、`年齡`、`性別`、`同處方` 之一，多種時以 `+` 連接，例如 `年齡+同處方`；`條件` 依同樣順序寫成以 `;` 分隔的幾段，例如 `>=65;G04CA C02CA`。年齡寫 `>=65`（65 歲以上）或 `<50`（未滿 50 歲）；性別寫 `男` 或 `女`；同處方的 ATC 後面加 `@HS` 表示那個藥的頻率含 HS 才算（HS、QHS、HSPRN、QD&HS 等），例如 `C08@HS`。

## 各檔欄位

| 檔案 | 欄位 |
|---|---|
| `indications.csv` 適應症 | ATC、藥理類別（說明用）、可解釋的ICD-10、依據、備註（說明用） |
| `co-drugs.csv` 同處方 | ATC、可由同處方的ATC解釋、依據、備註（顯示在理由裡） |
| `cautions.csv` 注意事項 | 編號、ATC、成分關鍵字（大寫，比對健保成分）、條件類型（診斷／年齡／性別／同處方，多種以 `+` 連接）、條件（診斷碼、`>=65`、`<50`、`男`／`女` 或 ATC，多段以 `;` 分隔）、等級、提示（顯示的文字）、依據（說明用） |
| `specialty.csv` 科別常用 | 科別代碼（健保就醫科別 2 碼）、科別（說明用）、該科常開的ATC |
| `drug-classes.csv` 藥品分類 | ATC、類型（低風險／高警訊）、說明（說明用） |
| `settings.csv` 設定 | 設定、值、可選的值、說明。`同成分重複`：紅／黃／灰；`科別常用`：保留／停用 |

## 修改流程

1. 改 CSV。表頭不要動；用 Excel 編輯時另存成「CSV UTF-8」。
2. 執行 `npm run rx-assets`。格式不對時會停下，並指出哪個檔、第幾列、哪一欄。
3. 執行 `npm test`。`public/assets/rx/rules.json` 沒有重產時測試會失敗。
4. 有本機樣本時，可另外跑和原型的比對（見下方）。比對只看邏輯：原型會改用 repo 裡的規則表，所以改規則不會讓比對失敗；但 `settings.csv` 要是原型的做法（同成分重複＝黃、科別常用＝保留）。
5. 照一般流程開 PR。

## 試跑與比對

規則起草時，用同事以收集頁（`collect/`）收來的 171 張去識別化處方試跑：558 個藥品，14 張處方（8%）出現黃色警示，沒有紅色。規則是照這批樣本調的，所以 8% 偏樂觀；同事會再收 100～200 張新樣本驗證。樣本與試跑結果都留在本機，不放進 repo。

**第一次驗證（115/10/31）**：用 94 張起草時沒看過的新樣本，在規則未調整的情況下試跑：282 個藥品，5 張處方（5%）出現黃色警示，沒有紅色。其中 3 張是值得確認的警示（NSAID 加十二指腸潰瘍；amlodipine 單方加含 amlodipine 的複方，2 張），2 張是規則缺口：免疫抑制劑配器官移植（Z94.4），以及含心衰竭的合併碼 I11.0。依這批樣本補上：calcineurin 抑制劑（L04AD）、心衰竭合併碼（I11.0 I13.0 I13.2）、硝酸鹽類與 nicorandil（C01D）、ATC 歸在 N02BA01 的 aspirin，以及皮膚科（科別常用、acitretin、外用 calcineurin 抑制劑）。補過之後這批也算看過了，下次驗證要再收新樣本。

`tests/rx-check-samples.test.ts` 用這批樣本確認 TypeScript 版和原型對每個藥的判定、理由、注意事項，以及診斷碼的中文名稱都一致（目前 265 張全部一致）。沒設環境變數時跳過：

```bash
RX_SAMPLES="樣本1.txt;樣本2.txt" RX_PROTOTYPE=../rx-rules-draft/check_rules.py npm test
```

`RX_SAMPLES` 的多個檔案在 Windows 以 `;`、其他系統以 `:` 分隔。測試只印出張數與不一致的樣本行號，不印樣本內容。

## 藥師審核

藥師在審核頁逐條看規則（每條附依據、樣本中的命中次數，ATC 碼附中文類別、成分與商品名），選同意、不同意或其他意見。審核頁與命中次數來自本機樣本，不放進 repo；這裡只記錄決定與改了什麼。

### 第一批（115/11/01）

審核頁共 161 條：規則表的每一列、`settings.csv` 的 2 項設定，以及 3 個待決定的問題。這批審了 129 條：

- **同意，照原樣保留（115 條）**：`indications.csv` 69 列、`cautions.csv` 11 列、`specialty.csv` 15 科、`drug-classes.csv` 17 列、`settings.csv` 2 項（同成分重複＝黃、科別常用＝保留），以及「警示只在憑單模式、預設關閉、網址加 `?rxcheck=1` 試用」。先前標出的依據與備註不一致的 3 列（SGLT2 抑制劑配心衰竭與慢性腎病套用整個 A10BK、β 阻斷劑與鈣離子阻斷劑配心絞痛套用整個 C08CA、Hydroxychloroquine 依據寫仿單）都同意照現狀；腦循環與認知用藥（N06BX N06DX）同意，拿掉備註的「待審」。
- **依意見修改（12 條，已改）**：
  - `cautions.csv` **C05**（SGLT2 抑制劑＋泌尿道或生殖道感染，評估是否暫停）：不同意，刪除。停藥不會減少感染復發，反而增加心腎風險。
  - `cautions.csv` **C15**（65 歲以上用 desmopressin）：灰色改黃色，提示加上「請詢問有無噁心、食慾下降、體重增加、倦怠嗜睡等症狀」。
  - `specialty.csv`：這些藥跟診斷走，不算該科常開，所以從科別常用拿掉：外科（03）的荷爾蒙拮抗劑 L02B（外科只有這一類，整列刪除）、骨科（06）的 A02、消化內科（AA）的 J05AF、腎臟內科（AD）的 C08 C09 C10 A10BK M04。這些藥在 `indications.csv` 都有對應的診斷（例如 J05AF 配 B16-B19、L02B 配 C50 C61、M04 配 M10）。
  - 讀不到生日時，年齡注意事項原本寫「無法判斷：AGE?99/99/99 跨過 65 歲」，改成「無法讀取年齡」。
  - `cautions.csv` **C09**（65 歲以上用 BZD／Z-drug，灰色）：同意；同處方有睡前（頻率含 HS）服用的降血壓藥，或攝護腺用的 α 阻斷劑（例如 doxazosin〔Doxaben〕、tamsulosin〔Harnalidge〕）時升一級。新增 **C17**（黃色，條件 `年齡+同處方`、`>=65;G04CA C02CA C02@HS C03@HS C07@HS C08@HS C09@HS`），成立時取代 C09。
  - `indications.csv` 5α 還原酶抑制劑（G04CB）配良性攝護腺增生：同意；另外，可能懷孕的女性不應接觸此藥，50 歲以下女性的處方有此藥時要給紅色。新增 **C18**（紅色，條件 `性別+年齡`、`女;<50`）。性別取自身分證字號第 2 碼，第 2 碼不是 1 或 2 時當作無法取得性別資料；收集頁也改成在第 5 欄記 `SEXM`／`SEXF`，之後收的樣本才能驗證這條（之前的樣本第 5 欄都是空白）。
  - `co-drugs.csv` 3 列（胃藥配抗血小板藥等、瀉劑配鴉片類、葉酸配 methotrexate 與抗癲癇藥）：同意；因為別的藥而開的藥也應提示，但不必到黃色。網頁改把這類藥列為灰色提示，理由裡同處方的藥附上藥名。
