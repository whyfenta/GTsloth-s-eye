# 處方警示規則表（草稿）

> **狀態：藥師審核中。** 規則表由先前的開發 session 憑藥學知識起草，尚未逐條對照仿單。「依據」欄（仿單、指引、常見、常見仿單外）是起草者的判斷，不是查證過的結果。藥師已審過第一批（見下方「藥師審核」），還有 78 條待審（含 115/11/03 加入的藥品併用 23 條、115/11/04 加入的 2 條、115/11/05 第二次驗證提出的 17 條），以審核頁為準。審完第一批後網站的處方警示改為預設開啟，未審的規則照原樣生效、陸續審核；開關見 README「處方警示」。

檔案：[`rx-rules/`](rx-rules/) 底下 6 個 CSV，UTF-8（含 BOM）。前 5 個（適應症、同處方、注意事項、科別、藥品分類）從規則草稿資料夾原樣複製；`settings.csv` 是這次新增的，把需要藥師決定的做法從程式移到表格。

用途：`npm run rx-assets` 逐列檢查後轉成 `public/assets/rx/rules.json`，由 `src/rx-check.ts` 判定。判定邏輯照規則草稿的 Python 原型 `check_rules.py`（不在 repo 裡），兩者對每個藥的判定以本機樣本比對一致，見下方「試跑與比對」。

## 判定方式

每個藥依序判定，前一層解釋得了就停：

1. **適應症**（`indications.csv`）：本次的某個診斷碼可以解釋這個藥。同一個藥對到多列時，依「依據」先試仿單、再指引、常見、常見仿單外，其他寫法最後；同一種依據照檔案順序。
2. **同處方**（`co-drugs.csv`）：同一張處方上的另一個藥可以解釋它，例如抗血小板藥解釋胃藥。同一個健保碼開兩次不算。網頁仍把這類藥列為灰色提示（藥師審核：因別的藥而開的藥也要提示，但不必到黃色）。
3. **科別常用**（`specialty.csv`）：QR 第 7 欄的就醫科別常開這類藥。`settings.csv` 可以停用這一層。
4. **低風險**（`drug-classes.csv` 類型「低風險」）：不提示。
5. 都解釋不了：高警訊藥（`drug-classes.csv` 類型「高警訊」）給黃色，其他給灰色。處方沒有診斷碼時一律灰色。

另外：

- **注意事項**（`cautions.csv`）：不論上面判定的結果，每個藥都另外比對。藥品以 ATC 或成分關鍵字對上後，看條件：診斷（本次有這些診斷碼）、年齡（年齡層至少幾歲或未滿幾歲）、性別（QR 第 5 欄身分證字號的第 2 碼：身分證 1 男、2 女；統一證號新式 8 男、9 女，舊式 A、C 男，B、D 女）、同處方（同一張處方有這些 ATC 的藥，可限定那個藥的頻率）。一條可以有多種條件，全部成立才提示；有一種不成立就不提示；其餘成立、但有一種無法判斷時給灰色：年齡層跨過門檻時「無法判斷」，沒有生日或生日格式認不得時「無法讀取年齡」，第 2 碼不是上述字元（或沒有字號）時「無法取得性別資料」。
- **較具體的注意事項取代較一般的**：同一個藥同時對到兩條注意事項，若兩條的 ATC 與成分關鍵字寫得一樣，而一條的條件包含另一條的全部條件還多幾項，只顯示條件多的那條。例如 C17 是 C09（65 歲以上用 BZD，灰色）再加上同處方有 α 阻斷劑或睡前降血壓藥，成立時只顯示黃色的 C17，這就是 C09「升一級」。
- **同成分重複**：同一張處方兩個以上不同健保碼含相同成分時提示，等級在 `settings.csv`。成分名去掉含量（MG、MCG、G、ML、IU、U、%）、括號與鹽類字尾（HCL、SODIUM 等）後比對，所以 INSULIN GLARGINE 和 INSULIN ASPART 仍是兩個成分。
- **沒有診斷碼的處方**：整張只給一則灰色提示，不對每個藥逐一提醒；注意事項照常比對。
- **不在健保用藥品項的代碼**（例如特材）：當成低風險，也不比對注意事項。
- 診斷碼比對前，QR 與規則兩邊都去掉小數點並轉成大寫。
- **同一病人的多張處方合併比對**（憑單畫面）：同一病人（身分證字號相同；讀不到字號時姓名與生日都相同）同時交付的多張處方，把全部的診斷與全部的藥品當成一張來判定（`checkPrescriptions`）：適應症、注意事項的診斷條件看全部的診斷；同處方解釋與注意事項的同處方條件看全部的藥（先找同一張上的藥）；同成分重複也跨張計算，同一個健保碼開在兩張處方算重複（同一張上開兩次不算）。科別常用只看藥品自己那張處方的科別；年齡層與性別取第一張有資料的。理由用到別張處方的診斷或藥時，前面標出「第 n 張」，別張的藥以「併用：」開頭、同一張的照舊寫「同處方：」。只有一張處方時結果與原本完全相同，原型比對與處方樣本的判定摘要（每一行單獨計算）都不受影響。

## 寫法

- 一格有多個值時以半形空格分隔。
- **ATC**：寫前綴，例如 `C`（所有心血管藥）、`C10`、`C10AA`、`C10AA05`。
- **ICD-10-CM**：寫前綴，例如 `E11`、`N18.4`；或寫範圍，例如 `I10-I16`。範圍兩端的碼長要相同、前小後大，比對時取診斷碼的前幾碼（與範圍兩端同長）落在兩端之間，所以 `I20-I25` 包含 `I25.10`、不包含 `I26`。
- 等級只能是 `紅`、`黃`、`灰`。
- **注意事項的條件**：`條件類型` 寫 `診斷`、`年齡`、`性別`、`同處方` 之一，多種時以 `+` 連接，例如 `年齡+同處方`；`條件` 依同樣順序寫成以 `;` 分隔的幾段，例如 `>=65;G04CA C02CA`。年齡寫 `>=65`（65 歲以上）或 `<50`（未滿 50 歲）；性別寫 `男` 或 `女`；同處方的 ATC 後面加 `@HS` 表示那個藥的頻率含 HS 才算（HS、QHS、HSPRN、QD&HS 等），例如 `C08@HS`。

## 各檔欄位

| 檔案 | 欄位 |
|---|---|
| `indications.csv` 適應症 | ATC、藥理類別（說明用）、可解釋的ICD-10、依據、備註（說明用） |
| `co-drugs.csv` 同處方 | ATC、可由同處方的ATC解釋、依據、備註（顯示在理由裡） |
| `cautions.csv` 注意事項 | 編號、ATC、成分關鍵字（大寫，比對健保成分）、條件類型（診斷／年齡／性別／同處方，多種以 `+` 連接）、條件（診斷碼、`>=65`、`<50`、`男`／`女` 或 ATC，多段以 `;` 分隔）、等級、提示（顯示的文字）、依據（說明用） |
| `specialty.csv` 科別常用 | 科別代碼（健保就醫科別 2 碼）、科別（說明用）、該科常開的ATC |
| `drug-classes.csv` 藥品分類 | ATC、類型（低風險／高警訊）、說明（說明用） |
| `settings.csv` 設定 | 設定、值、可選的值、說明。`同成分重複`：紅／黃／灰；`科別常用`：保留／停用 |

## 修改流程

1. 改 CSV。表頭不要動；用 Excel 編輯時另存成「CSV UTF-8」。
2. 執行 `npm run rx-assets`。格式不對時會停下，並指出哪個檔、第幾列、哪一欄。
3. 執行 `npm run rx-review-page -- 樣本…`，再把產生的清單寫進審核頁（見下方「審核頁」）。新條文和改過內容的規則會出現在藥師的待審。
4. 執行 `npm test`。`public/assets/rx/rules.json` 沒有重產，或 `docs/reference/rx-rules-review.json` 沒有更新時，測試會失敗。
5. 有本機樣本時，可另外跑和原型的比對（見下方）。比對只看邏輯：原型會改用 repo 裡的規則表，所以改規則不會讓比對失敗；但 `settings.csv` 要是原型的做法（同成分重複＝黃、科別常用＝保留）。
6. 照一般流程開 PR。

## 試跑與比對

規則起草時，用同事以收集頁（`collect/`）收來的 171 張去識別化處方試跑：558 個藥品，14 張處方（8%）出現黃色警示，沒有紅色。規則是照這批樣本調的，所以 8% 偏樂觀；同事會再收 100～200 張新樣本驗證。樣本與試跑結果都留在本機，不放進 repo。

**第一次驗證（115/10/31）**：用 94 張起草時沒看過的新樣本，在規則未調整的情況下試跑：282 個藥品，5 張處方（5%）出現黃色警示，沒有紅色。其中 3 張是值得確認的警示（NSAID 加十二指腸潰瘍；amlodipine 單方加含 amlodipine 的複方，2 張），2 張是規則缺口：免疫抑制劑配器官移植（Z94.4），以及含心衰竭的合併碼 I11.0。依這批樣本補上：calcineurin 抑制劑（L04AD）、心衰竭合併碼（I11.0 I13.0 I13.2）、硝酸鹽類與 nicorandil（C01D）、ATC 歸在 N02BA01 的 aspirin，以及皮膚科（科別常用、acitretin、外用 calcineurin 抑制劑）。補過之後這批也算看過了，下次驗證要再收新樣本。

**持續收集（115/11 起）**：憑單模式列印時自動送出去識別化樣本，每週一整理成「驗證用」裡的 `處方QR去識別化_自動_*.txt` 與「每週檢查」的週檢查資料，再由排程的 Claude 寫審閱報告（流程見 README「處方樣本試算表」與 [`../rx-samples-weekly-review.md`](../rx-samples-weekly-review.md)）；報告除了檢討出現的警示，也逐張找規則沒抓到的問題（`rx-try --detail`），並用累計的匯出檔看每條注意事項的覆蓋度（`rx-try --coverage`）。審閱只提建議；要採用的修改照上方「修改流程」處理，可以先用 `npm run rx-try -- 樣本.txt` 比較修改前後哪些處方的判定改變。用來調整過的樣本移到「已用於調整」。統一證號的性別從 115/11 起才判讀（之前第 2 碼是 8、9、A～D 的樣本第 5 欄都是空白）。

**第二次驗證（115/11/05）**：用同事新收的 97 張（和先前 265 張沒有重複），在規則未調整的情況下試跑：269 個藥品，8 張處方（8.2%）出現黃色警示，沒有紅色。其中 7 張是值得確認的警示：BZD 配 α 阻斷劑或睡前降血壓藥（C17，2 張）、BZD 配失智症（C42，2 張，其中 1 張同時有抗精神病藥配失智症 C10）、沒有糖尿病診斷卻開 metformin（2 張）、methylphenidate 長效加短效（同成分重複）。另外 1 張是皮膚科 azathioprine 的規則缺口。C18、C19–C41、C43 在這批沒有命中。這批多了性別欄（87 張有 SEX 標記）。依這批提出的規則與問題見「藥師審核」的「第二次驗證」；這批也算看過了，放在 Drive 的「已用於調整」。先前 265 張用同一版規則重跑：黃色 23 張（8.7%），沒有紅色。

資料問題：有 3 家院所的生日是 6 碼（`AGE?999999`，362 張裡共 8 張），讀不到年齡，年齡條件的注意事項都只能給灰色「無法讀取年齡」；去識別化後看不出是哪種格式，要看一張原始 QR 才能修。有 1 家院所用院內 3 碼科別（`010`、`003`、`0D6` 等），都當作未知科別。這批有 4 家院所的第 5 欄沒有性別標記（共 10 張），性別條件的注意事項會給灰色。

`tests/rx-check-samples.test.ts` 用這批樣本確認 TypeScript 版和原型對每個藥的判定、理由、注意事項，以及診斷碼的中文名稱都一致（目前 362 張全部一致）。沒設環境變數時跳過：

```bash
RX_SAMPLES="樣本1.txt;樣本2.txt" RX_PROTOTYPE=../rx-rules-draft/check_rules.py npm test
```

`RX_SAMPLES` 的多個檔案在 Windows 以 `;`、其他系統以 `:` 分隔。測試只印出張數與不一致的樣本行號，不印樣本內容。

## 藥師審核

藥師在審核頁逐條看規則（每條附依據、樣本中的命中次數，ATC 碼附中文類別、成分與商品名），選同意、不同意或其他意見。命中次數來自本機樣本，只存在審核頁；這裡只記錄決定與改了什麼。

### 審核頁

審核頁是 claude.ai 上的 Artifact「處方警示規則審核」（私人頁面；Claude 用 `Artifact` 的 `list` 找得到）。藥師的決定存在頁面的資料庫 `reviews/<藥師 id>`，規則清單存在 `catalog/current`。頁面開著時，清單一更新畫面就會跟著變，不必重新發布頁面。

規則表有新增或修改時：

1. 執行 `npm run rx-review-page -- 樣本1.txt 樣本2.txt …`（不給樣本就不含命中次數）。它更新 `docs/reference/rx-rules-review.json`，並產生 `tmp/rx-review/catalog.json`。新規則需要說明時，加 `--notes 說明.json`：為什麼提出、出處連結、新問題、ATC 中文名（格式見 `scripts/rx-review-page.ts` 開頭）。`rx-rules-review.json` 在公開的 repo 裡，說明只寫張數與藥品組合，不寫院所代碼或某張處方的年齡層（`npm test` 會檢查）。
2. Claude 用 `ArtifactData` 的 `get` 讀 `catalog/current` 的版本，再用 `set` 把 `tmp/rx-review/catalog.json` 寫進去（`if_version` 帶剛讀到的版本）。

判定方式：

- `rx-rules-review.json` 記每條規則的編號、內容指紋、所屬批次、最後改變時間、提出原因與處理結果；不含樣本內容，也不含藥師的決定。適應症等沒有編號的列，編號只看內容，列的順序變了也不會變。
- 內容指紋只看會改變判定的欄位，改 `備註`、`說明` 不算改規則。
- 決定的時間早於規則的最後改變時間，就算過期：這條回到待審，頁面顯示原本的內容，舊的決定留著參考。如果改動就是照藥師的意見改的，在 `--notes` 的該條加 `applied`（處理結果），不會回到待審。
- 從規則表拿掉的規則進「已刪除」，舊的決定留著。

藥師審完後，請 Claude 用 `ArtifactData` 讀 `reviews`，依決定改規則表，照上面的「修改流程」處理，再把決定與改動記在這一節。

### 藥品併用（115/11/03 加入，未審）

`cautions.csv` 原本只有 C16（鴉片類＋BZD）一條是兩個藥同處方的注意事項。這次加入 C19–C41 共 23 條（紅 8、黃 12、灰 3），每條都以現有的條件寫法（同處方，必要時加診斷、年齡或性別）表達。來源以 Beers 2023 表 5（老人應避免的藥物併用，PMC 全文逐列核對）為主，其餘是 FDA、EMA 的安全通訊與仿單；「依據」欄寫的是網路上找到的出處，沒有逐條對照國內仿單，fluoroquinolone 黑框警語與 allopurinol 減量幅度只找到二手轉述（Beers 表 2 在 115/11/05 核對過原文，見「第二次驗證」）。等級是起草時填的，審核時決定。

試跑 265 張本機樣本（「已用於調整」）：只有 C19 命中 1 張，那張原本就有黃色警示，所以黃紅處方仍是 20 張。兩邊的藥都出現過、但沒開在同一張的有 C20（clopidogrel 9 張、omeprazole／esomeprazole 1 張）、C24、C26、C29、C33、C39。這批樣本多是慢性病處方（fluoroquinolone 0 張、全身性類固醇 2 張），C21、C22、C25、C37 實際上沒測到；性別欄全是空白，C41 也還驗證不到。

現有寫法做不到、這次沒有加的：同時用 3 種以上中樞神經藥（Beers 表 5，要能數藥數）；NSAID＋RAS 阻斷劑＋利尿劑（一條只能寫一個同處方條件）；跟劑量有關的上限（例如 simvastatin 併用 amlodipine 最多 20 mg）；「有開胃藥就不提示」這類排除條件。

同時修正：ATC 的 `M01A` 不只有 NSAID，還包含 glucosamine（M01AX05）與 chondroitin（M01AX25），所以 C07 會把 glucosamine 配慢性腎病當成 NSAID 給黃色，胃藥那列 `co-drugs.csv` 也會由 glucosamine 解釋。兩處改成列出 NSAID 的 ATC：`M01AA M01AB M01AC M01AE M01AG M01AH M01AX01 M01AX02 M01AX07 M01AX17 M01AX91`，C23–C25 用同一串（265 張樣本裡沒有因此改變判定的處方）。之後健保用藥品項出現新的 M01AX 成分時，要另外判斷算不算 NSAID。`indications.csv` 的 NSAID 列（`M01A M02A`）不改：glucosamine 由肌肉骨骼診斷解釋是對的。

### 跨科處方的老人用藥（115/11/04 加入，未審）

憑單改成同一病人的多張處方合併比對後，用一份同一病人三科處方的範本（內分泌、心臟內科、神經科）試跑，現有規則只給一則灰色 C09。範本裡有兩個跨科的問題沒有規則，這次加入 2 條，都以現有寫法表達：

- **C42（黃）BZD／Z-drug＋失智症或認知障礙**：範本是心臟內科開 lorazepam、神經科診斷失智症。條件是診斷 `F01-F03 G30 G31.0 G31.1 G31.83 R41.81`（血管性與其他失智症、阿茲海默、額顳葉失智症、老年性腦退化、路易氏體、年齡相關的認知能力下降）。藥品除了 C09 那串 BZD／Z-drug 的 ATC，另以成分關鍵字 `CHLORDIAZEPOXIDE` 涵蓋含 chlordiazepoxide 的複方：健保用藥品項裡有胃腸複方（A02AG，制酸劑＋scopolamine＋dicyclomine＋chlordiazepoxide）、Librax 類（A03CA02）與 amitriptyline 複方（N06CA01），ATC 都不在 N05BA。依據 Beers 2023 表 3（失智症或認知障礙應避免 BZD 與 Z-drug）。
- **C43（灰）65 歲以上 SGLT2 抑制劑＋利尿劑**：範本是內分泌開 empagliflozin、心臟內科開含 HCTZ 的三合一降血壓複方（C09DX03）。藥品以 `A10BK` 加成分關鍵字 `GLIFLOZIN`，涵蓋 SGLT2 抑制劑的複方（A10BD15、A10BD19、A10BD20、A10BD21、A10BD24）。同處方條件除了 `C03`，另列健保用藥品項裡含利尿劑的降血壓複方：`C02L C07B C07C C07D C08G C09BA C09BX01 C09DA C09DX01 C09DX03 C09XA52 C09XA54`；只寫 `C03` 時範本不會觸發。依據是仿單警語（老人與併用利尿劑者需評估體液），沒有對照國內仿單。起草時給灰色：心衰竭與慢性腎病的病人常同時用這兩類藥，給黃色可能太常出現，審核時決定。

試跑：範本的合併比對多了黃色 C42（第 2 張 lorazepam，本次：第 3 張失智症）與灰色 C43（第 1 張 empagliflozin，併用：第 2 張含 HCTZ 的複方）；合成處方確認胃腸複方配阿茲海默、SGLT2 複方配 losartan／HCTZ、atenolol／chlorthalidone、furosemide 都會觸發，SGLT2 配單方 amlodipine 不會。本機 265 張樣本這次沒有重跑。

## 後續工作

複方的每個成分都能套用規則（例如含 HCTZ 的降血壓複方也算利尿劑）、每日劑量上限、同類不同成分的重複用藥、跌倒風險藥物的累計、藥名相似（LASA）提示、左右眼比對、過敏比對、給付期間檢查、規則表的出處與審核欄位，以及接入食藥署「全部藥品許可證資料集」的適應症原文。
