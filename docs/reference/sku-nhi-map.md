# 商品代號對照檔

檔案：`sku-nhi-map.csv`，放在**另一個 private repo**（例如 `whyfenta/GTsloth-map`），不放在這個公開 repo，因為它記錄整個商品檔的六碼與品名。UTF-8（含 BOM），6 欄，一個六碼一列，依六碼排序。

這個 repo 只放格式說明與工具，並用三道關卡防止對照檔被公開：

- `.gitignore` 排除 `sku-nhi-map*.csv`。
- `npm run audit:source` 會擋下被強制加入（`git add -f`）的對照檔，CI 因此變紅。
- `npm run nhi-map` 拒絕使用位在本 repo 內、又沒被 Git 排除的對照檔。

用途：記錄門市商品代號（六碼，全門市共用）對到的健保藥品代號。庫存簡表沒有健保碼欄位，國際條碼也不在健保檔中，兩邊只能用名稱比對。同一個六碼確認過一次後，之後各門市的庫存簡表都直接查表，只有新的六碼或品名改變的六碼才重新比對。網站不內含這個檔案；樹懶的算數的領藥憑單可由使用者在頁面選取載入（只留在頁面記憶體），把 QR 的健保碼反查成六碼與品名，見 README「商品對照檔」。

## 欄位

| 欄位 | 說明 |
|---|---|
| 六碼 | 商品代號，6 位數字，以字串保存。 |
| 健保藥品代號 | 10 碼；判定為「無健保碼」時留空。這裡只存代號，支付價與是否給付每次都從最新的 [`nhi-drug-codes.csv`](nhi-drug-codes.md) 查。 |
| 對接品名 | 確認當時的庫存簡表品名，去掉狀態字（避光、缺貨、追追、換包、近效、停供、自費等）、`C-` 類別標記與尾端的 `-高健保`、`-高價藥`，**保留包裝規格**，例如 `1000粒/盒(10粒/排)IWELL宜胃錠(複方)`。只有狀態字改變時仍算同一品名；包裝或品名改變（例如換包後從瓶改盒）就重新比對，因為 00 與 G0 碼可能要換。 |
| 判定 | `自動明確`（程式比對）、`人工確認`（人工選定）或 `無健保碼`（人工確認沒有健保碼，如自費品）。 |
| 判定日期 | `YYYY-MM-DD`。 |
| 來源 | 確認時所用庫存簡表的門市與列印日，例如 `26北-永和福和店 2026-10-11 列印`。 |

不直接加欄位到健保精簡檔，原因如下：

- 一個健保碼可能對到多個六碼。
- 同一藥品的 00 與 G0 碼要依六碼的包裝選。
- 健保檔更新時是整份換新。

## 設定

1. 在 GitHub 建立 private repo（例如 `GTsloth-map`），clone 到這個 repo 旁邊：

   ```
   GTsloth-s-eye/    ← 這個公開 repo（程式）
   GTsloth-map/      ← private repo，放 sku-nhi-map.csv
   ```

2. 每次執行用 `--map` 指定對照檔，或先設定環境變數 `SKU_NHI_MAP`，之後就不必每次指定：

   ```
   npm run nhi-map -- --map ../GTsloth-map/sku-nhi-map.csv 庫存簡表.pdf
   ```

   - macOS／Linux：`export SKU_NHI_MAP=../GTsloth-map/sku-nhi-map.csv`
   - Windows PowerShell：`$env:SKU_NHI_MAP = "..\GTsloth-map\sku-nhi-map.csv"`

   兩者都有時以 `--map` 為準；都沒有時程式不執行。相對路徑以這個 repo 的根目錄為準（`npm run` 在這裡執行）；找不到對照檔所在的資料夾時，程式提醒先 clone private repo。

3. 對照檔還不存在時從空白開始，第一次 `--write` 或 `--apply` 時建立（含表頭）。每次寫入後到 `GTsloth-map` commit、push。

4. 在 Claude 雲端工作階段使用時，工作階段也要能存取 `GTsloth-map`，即 Claude GitHub App 的存取範圍要包含這個 repo。

5. 設定 `SKU_NHI_MAP` 後執行 `npm test`，會額外檢查對照檔格式，以及其中每個健保碼都在健保檔裡。沒設定時這項略過，CI 也不會讀到對照檔。

## 使用方式

需要系統列印的文字 PDF 庫存簡表（與「樹懶的管理」相同的要求），可一次放多份；含零庫存列印的簡表涵蓋整個商品檔。以下指令都假設已設定 `SKU_NHI_MAP`，否則請加上 `--map …`。

```
npm run nhi-map -- 庫存簡表.pdf [更多庫存簡表.pdf …]
```

1. 每個六碼先查對照檔，查不到或品名改變才比對名稱。結果寫到 `output/nhi-map/`（Git 不追蹤）：
   - `<檔名>-查表.csv`：每個六碼的健保碼、英文名、中文名、指定日期的給付狀態與查表結果。
   - `<檔名>-待確認.csv`：需要人工判斷的六碼，附原因、品名標記（自費、停供等）、庫存量、目前對照與最多 5 個候選（代號｜英文名｜中文名｜劑型與規格量｜藥商｜給付狀態｜分數與依據）。
2. 不加參數時不改對照檔。確認結果後加 `--write` 重跑，寫入新的自動明確與品名更新，再到 private repo commit 對照檔。
3. 人工判斷：在待確認表的「採用」欄填健保藥品代號，或填 `無` 表示沒有健保碼，空白的列略過。接著執行：

   ```
   npm run nhi-map -- --apply output/nhi-map/<檔名>-待確認.csv
   ```

   填健保碼者寫成人工確認，填 `無` 者寫成無健保碼。用 Excel 編輯後另存也可以讀回：六碼的前導零會補回，Big5 編碼也能讀。只要有一列有誤（例如健保檔沒有該代號），整份都不寫入。
4. 健保檔更新後執行 `npm run nhi-map -- --check`，結果寫到 `output/nhi-map/對照檔檢查.csv`。這份檢查會列出對照檔中有以下情形的健保碼：
   - 已不在健保檔
   - 當天未給付
   - 已排定停止給付或調價

   有同藥證的現行碼時一併列出。
5. `--date YYYY-MM-DD` 指定判斷給付的日期，預設今天（台灣時間）。健保檔只含下載當時已公告的異動，日期離資料基準日越遠，結果越可能過時。

## 查表規則

| 情況 | 結果 |
|---|---|
| 六碼在對照檔，對接品名相同 | 直接採用，不比對 |
| 品名改變，重新比對結果與對照檔相同（原為無健保碼時，仍找不到候選也算相同） | 只更新對接品名、判定日期與來源，判定不變 |
| 品名改變，原判定為自動明確，重新比對為明確 | 以新結果取代，仍為自動明確 |
| 品名改變，原判定為人工確認或無健保碼，重新比對結果不同 | 列入待確認「品名已變更」，不自動覆寫 |
| 六碼不在對照檔 | 比對名稱；結果明確的成為自動明確，其餘列入待確認 |
| 對照的健保碼當天未給付，但同藥證另有現行碼 | 照常查出，另列入待確認「對照碼今日未給付」，候選為同藥證的現行碼 |

## 名稱比對

程式在 `scripts/nhi-match.ts`，對照檔的讀取與格式檢查在 `src/sku-map.ts`（與網站共用），寫入與查表在 `scripts/sku-map.ts`。

- **候選來源**：英文品牌名，或中文品名主體（去掉膜衣錠、膠囊、點眼液等劑型字）。英文名容許以下差異：
  - 健保英文名前多了廠名，如 OTSUKA ABILIFY。
  - 店內縮寫，如 Telmisart；只對到縮寫時，中文名也要吻合（FLUCORT 不是 FLUCORTONE）。
  - 連字號或句點寫法不同，如 U-CA 與 U-Ca、O.N.S.D。
- **計分**：
  - 英文名、中文名、中文全名。
  - 含量：
    - MG、MCG、G 互相換算。
    - %、mg/mL、mg/g 互相換算。
    - 複方含量，如 5/80MG。
    - 顆粒劑的 40MG 對應 40MG/GM。
    - 針筒、注射筆的 4KIU/0.4ML、300IU/3ML 同時算總量、濃度與容量。
    - 健保品名多出店內品名沒有的含量時扣分，例如 Co-Diovan 80/12.5 對 Diovan 80。
  - 不帶單位的數字，如使肺泰250。
  - 劑型：錠、膠囊、顆粒、外用、液劑、吸入、注射、栓劑、貼片須一致。持續性、口溶、腸溶等釋放型，以及乳膏、軟膏、凝膠的差別只扣分。
  - 用藥部位：眼、鼻、耳、陰道須一致（健保檔的劑型若只寫錠劑，也看品名的「陰道錠」）。
  - 包裝規格量，如 5G、10ML、200DOSE，不符的代碼直接排除。品名有「單支」時，健保檔也要是單支或單劑量包裝。
  - 品名中的［廠牌］（台田、中化、諾華等簡稱另有對照）。
  - (複方)。
- **同一產品**：第 1 碼與第 3–8 碼相同的代碼視為同一張藥證，算同一產品。
- **明確的條件**：以指定日期支付價大於 0 的現行碼為準。最佳的現行產品須達門檻，其他現行產品須至少低 2 分；同一產品裡要剛好剩一個現行碼。同時有 00 與 G0 現行碼時，品名包裝為「粒/盒」或含「(n粒/排)」選 G0，「粒/瓶」選 00。
- **不明確的分類**：
  - 多個候選
  - 同藥證多個現行碼
  - 只對到未給付碼
  - 品名廠牌與健保檔不符
  - 品名標示為食品（食品沒有健保碼，即使成分與某個藥品相同，如鳳梨酵素）
  - 找不到候選

## 驗證

測試資料配 115/10/25 健保檔。兩份庫存簡表都不放在這個 repo。

| 結果 | 26 永和福和店（2026/10/11 列印，1,002 個六碼） | 15 蘆竹南崁店，含零庫存（2026/10/12 列印，4,949 個六碼） |
|---|---|---|
| 自動明確 | 955 | 955 筆直接查表＋新比對 3,402 |
| 多個候選 | 9 | 84 |
| 同藥證多個現行碼 | 0 | 54 |
| 只對到未給付碼 | 2 | 134 |
| 品名廠牌與健保檔不符 | 0 | 6 |
| 品名標示為食品 | 0 | 2 |
| 找不到候選 | 36 | 312 |

- **26 永和的 955 個六碼**：在 0015 的簡表裡品名全部相同，證實六碼與品名全門市共用。
- **多個候選**：例如兩家廠同名的 CORTISONE、ALLOPURINOL；兩張藥證的 XARELTO、KALIMATE；未印含量的 TRIMBOW。
- **找不到候選**：多為沒有健保碼的自費品（威而鋼、犀利士、避孕藥等）。
- **26 永和人工檢視**：約 300 筆，包括所有分數與次佳現行產品相差 3 分以內、或英文名／中文名／含量未全部吻合的，沒有發現錯配。
- **0015 新比對人工檢視**：同樣條件的約 300 筆，另隨機抽 120 筆，發現 6 筆錯配：
  - FLUCORT 兩筆對到 FLUCORTONE。
  - EPREX 針筒對到另一容量。
  - 標示食品的鳳梨酵素對到藥品。
  - Latropine 單支裝兩筆對到 5 ML 瓶裝。

  已加規則修正：縮寫須中文名吻合、單支裝、食品、KIU 單位。修正後這 6 筆與另 2 筆（ZINGA 食品、RECORMON 新舊碼分數接近）改列待確認。另有 4 筆眼、耳用藥與注射劑因部位與單位判斷改進，新列為明確，已逐筆確認。26 永和的結果不變。其餘未逐筆核對。

設定 `MANAGEMENT_INVENTORY_PDF` 為 26 永和的簡表後，`tests/nhi-map.test.ts` 會重跑 26 永和的數字與 10 個已知對照。
